How to read this

This is the backbone — the scope-and-sequence plus a vetted resource map. It is built so a mixed group can all start at the same low floor and then climb as far as they want. The student-facing, work-through-it modules are a companion document; this one is the map they hang from. Two foundation modules — The Workbench (the professional dev environment and ecosystem) and Build in the Open (process and documentation) — run beneath every level as the "how professionals work" layer, and are companion documents too.

The design goal is the thing employers keep asking for and schools rarely teach: not "prompt an AI," but stand up open models on real hardware, serve them reliably, network machines together, and build tools and agents on top. That skill sits at the intersection of three worlds — AI concepts, Linux/networking infrastructure, and DevOps — which is exactly why no single course or certificate covers it yet. The progression treats that intersection as the destination.

A note on honesty in these materials

Some of what gets sold in this space is hype. Where a path is genuinely production-realistic, it's marked. Where something is a great teaching demo but not how you'd really run it, that's marked too. And where the industry simply has no credential yet, that's stated plainly rather than papered over. Students learn more from a map that admits its own edges.

The seven-level arc

Each level is a capability, not a week. In a pilot (club or independent study) a motivated student might reach Level 4–5 in a semester; the same levels become the unit structure when this grows into formal courses.

The levels in detail

Level 0

On-ramp — everyone starts here

Low floor · no prerequisites · the shared vocabulary

Before anyone touches a GPU, the whole group builds the same footing: enough Python to read and edit a script, enough command line to move around a machine, and an honest mental model of what a large language model is and isn't. Then a guided tour of the Hugging Face Hub so "open-weight model" stops being an abstraction — students open real model cards, see licenses, sizes, and quantized variants.

What students do

  • Work through the first chapters of the Hugging Face LLM Course (Transformers, how models are hosted).
  • Learn Python fundamentals and the terminal; make a free Hugging Face account.
  • Tour five real model cards and explain, in plain English, base vs instruct, parameter count, context length, and license.
PythonCommand lineHugging Face HubOpen vs closed weights
Cert alignment: Python Institute PCEP ($69, no prerequisites — the single most accessible credential in this whole map). Optional concept anchor: one foundational cloud-AI cert (AWS AI Practitioner, Azure AI-901, or Google GenAI Leader, all ~$100).
Level 1

Run — your first local model

One box · one model · the "it's alive" moment

The payoff level. A student pulls an open model onto a single GPU machine and chats with it — no cloud, no API key, entirely their own. Then the concept that makes it possible: quantization. Why a model shrinks to fit 16–24 GB, what GGUF is, and why the same model comes in a dozen sizes.

What students do

  • Install Ollama, pull an open model, and chat from the terminal.
  • Hit the model's OpenAI-compatible API (http://localhost:11434/v1/) from a short Python script — the concept that unlocks every later level.
  • Try the LM Studio GUI as a no-terminal alternative, and peek at llama.cpp to see the engine underneath.

Models that fit a single 16–24 GB GPU (verify exact version at term start)

  • Qwen3-8B — Apache 2.0, ungated. The safe default.
  • Google Gemma (smaller instruct variants) — Apache 2.0, ungated.
  • OpenAI gpt-oss-20b — Apache 2.0, ships quantized to ~16 GB.
  • Meta Llama 3.x 8B — capable, but gated: each student must accept Meta's license first.
Realistic & free

Prefer the Apache-2.0, ungated models (Qwen, Gemma, gpt-oss) so nobody is blocked waiting on a license acceptance. Save the gated Llama models for when students are ready to learn why licenses gate access.

Reasoning models & the frontier open weights

Two things worth naming out loud. First: Qwen is itself a frontier Chinese model (Alibaba) — the list here leads with one, it doesn't avoid them. The filter for this level is "fits and runs on a single 16–24 GB GPU," not national origin.

Second, for students who want a reasoning-style model that still fits one GPU: DeepSeek-R1 distills (the 7B Qwen-based and 8B Llama-based variants) are a great option — read each card's license, since the distills inherit their base model's terms. The true frontier open weights — the full DeepSeek V3/R1, Moonshot Kimi, Zhipu GLM, and Llama 4's larger mixtures — are hundreds of billions of parameters and do not fit a single classroom GPU. Serving those needs a multi-GPU node or a hosted API, which becomes its own advanced unit rather than a day-one download.

Teaching point: because these all run locally, the usual "my data leaves the building" worry is moot — the weights execute on your machine and nothing phones home. The real things to vet on any model, regardless of origin, are training-data provenance, built-in behavior, and license. Students should learn to read those off the model card.

Cert alignment: concepts here feed directly into NVIDIA NCA-GENL (see Level 2). No dedicated cert for local inference exists.
Level 2

Serve — like an organization would

From "runs on my machine" to "serves a whole class"

Ollama is the on-ramp; it is not how a company serves a model to hundreds of users. Here students step up to a production serving engine and meet the ideas that separate a hobby from a job: concurrency, throughput, and packaging. This is also where Linux and networking stop being background and become the actual work.

What students do

  • Serve a model with vLLM (high-throughput, OpenAI-compatible) — one model answering many students at once. TGI as the Hugging Face-native alternative.
  • Package a service in Docker — the single most transferable ops skill on this map.
  • Learn the networking that makes serving real: static IPs, ports, SSH into a headless box, a reverse proxy, and firewall basics.
vLLMTGIDockerLinuxSSH · ports · reverse proxy
If a Mac mini is in the mix

vLLM and TGI are built for NVIDIA GPUs — they're the serving path on the dedicated-GPU boxes, not on Apple Silicon. A Mac mini serves through Ollama, LM Studio, or Apple's own MLX (mlx-lm) framework instead, taking advantage of unified memory. That difference is a feature for the curriculum: students learn that "serve a model" means different engines on different hardware, and that the OpenAI-compatible API is what lets a Mac node and an NVIDIA node sit behind the same gateway in Level 3.

Cert alignment: NVIDIA NCA-GENL ($125, no prerequisites — the flagship on-target GenAI cert) for the concept layer; CompTIA Linux+ and Network+ for the infrastructure backbone (Tech+ is the gentler on-ramp to those).
Level 3

Network — turn the lab into one service

Ten boxes, one endpoint · where the hardware pays off

This is the level the lab was built for, and it's also where the honesty matters most. There are two very different things people mean by "networking computers for AI," and students should learn both while knowing which is which.

The realistic pattern (this is how it's really done)

Run one model per box, then put all the boxes behind a gateway — LiteLLM — which presents a single OpenAI-compatible endpoint, load-balances across the nodes, handles failover, issues API keys, and logs usage. This is "horizontal scaling of independent replicas," and it's exactly the AI-gateway pattern organizations run. nginx is the lower-level version and a great networking lesson.

The distributed-inference experiments (great to teach, not to productionize)

Splitting one large model across machines is genuinely educational and genuinely bandwidth-bound. On ordinary Ethernet these demonstrate the concept rather than beat a single good GPU:

  • vLLM tensor / pipeline parallelism (multi-node uses Ray) — wants fast interconnect to shine.
  • llama.cpp RPC backend — works, and its own docs call it "proof-of-concept" and "insecure; never run on an open network." That warning is itself a teachable security moment.
  • exo — active project, tuned toward Apple Silicon and Thunderbolt links. If a Mac mini joins the lab, exo becomes a genuinely good fit rather than a stretch — Apple Silicon is exactly the hardware it targets. On x86 Ethernet boxes, verify the current story before committing.

Optional advanced ops

Stand up a lightweight Kubernetes cluster with k3s across the lab and deploy the serving stack onto it. Heavyweight, but a strong résumé skill and the natural bridge to the certification below.

Don't oversell the cluster

The primary, real-world pattern for a room of separate single-GPU desktops is one model per box + LiteLLM. Frame the "split a model across the lab" tools as experiments that teach distributed systems — not as the way to get more performance out of the room. Students who understand why will be ahead of most professionals.

Cert alignment: CNCF KCNA ($250, no prerequisites) for the Kubernetes/cluster layer; CompTIA Network+ for the networking fundamentals.
Level 4

Extend — build tools with MCP

Give the model hands · the "USB-C for AI tools" layer

A model that can only talk is limited. The Model Context Protocol is the open standard — introduced by Anthropic in late 2024 and now adopted across the major AI vendors — that lets any AI app use any tool you build. Students build their own MCP server, expose a couple of tools, and connect it to a host. A motivated student can finish a first working server in an afternoon.

What students do

  • Follow the official "Build an MCP server" quickstart in Python or TypeScript (the two best-supported SDKs).
  • Work through the Hugging Face MCP Course (free completion certificate).
  • Drive their MCP tools from a local model via the OpenAI-compatible endpoint and an agent loop.
Honest limitation worth teaching

MCP standardizes the tool side, not the model side. The plumbing works with local models — but a small 7–8B model calls tools far less reliably than a frontier model. That gap is the lesson: it shows why larger, better-tuned models follow tool instructions more dependably.

Cert alignment: Hugging Face MCP Course completion certificate (free, unproctored — a shareable artifact, not an industry cert).
Level 5

Agents & RAG — reason and retrieve

Wire models into harnesses · chat with your own documents

Now the model becomes the engine inside a larger system. Students learn the agent-harness pattern on top of their local stack, and build the single most satisfying first project in this whole space: retrieval over their own documents.

What students do

  • Use smolagents (open, local-first, deliberately minimal) or the OpenAI Agents SDK + LiteLLM to point a real harness at a local model.
  • Build a RAG pipeline: embeddings (via sentence-transformers or Ollama) → a vector store (Chroma is easiest; FAISS shows the internals) → retrieve → answer. Fully local, fully free.
  • Work the Hugging Face Agents Course (free certificate) and compare their local harness to a frontier one (Anthropic's Claude Agent SDK).

Level 6

Build & capstone — ship something real

Vibe-code on the local stack · host it in the lab

Everything converges. Students build a genuine application on top of the models the lab serves — using AI-assisted "vibe coding" as an accelerator, while learning explicitly when to lean on it and when to read the generated code. The capstone is a networked, served, agentic system the lab actually hosts.

What students do

  • Build with local-model-friendly AI coding tools — Cline or Continue (open-source, point at local models) — and compare to Cursor / cloud tools.
  • Ship a capstone that touches the full stack: a served model (Level 2), behind the gateway (Level 3), using an MCP tool they built (Level 4), inside an agent or RAG app (Level 5).
  • Assemble a portfolio and sit any targeted certifications.
Vibe coding, taught honestly

The term comes from Andrej Karpathy (early 2025): describe intent in plain English, let the model generate, iterate — sometimes without reading the code closely. It is real and productive, and it is a double-edged sword for learning. Teach it as a skill with a switch: know when to vibe and when to read every line.

Cert alignment: capstone + portfolio is the credential here; students sit whichever certs fit their path (see the map below).

Certification map

The blunt finding first, because it shapes everything: there is no dedicated industry certification for self-hosting and serving open-weight models or clustering them. That skill is certified only indirectly, as the sum of a GenAI-concepts cert, infrastructure certs, and an ops cert. Every credential below was verified against the vendor's own certification page in August 2026; treat costs as approximate and re-check before committing budget.

The genuine gap — say it to students plainly

No vendor sells a "Self-Hosted LLM Serving Engineer" badge. The résumé story is "I hold the GenAI-concepts cert (NVIDIA) plus the infrastructure and ops certs that make serving possible" — and, more convincingly, "here is the system I built and hosted." The portfolio is the real credential; the certs are supporting evidence.

Teacher & lab setup notes

Before day one

Get each machine to a known baseline: Linux (or WSL on Windows), current NVIDIA drivers, Docker, and Python. Confirm the exact VRAM on each GPU — it sets the ceiling on model size. Have every student create a free Hugging Face account in advance; if you plan to use gated Llama models, walk the license-acceptance step early because approval can take time. Lean on ungated Apache-2.0 models (Qwen, Gemma, gpt-oss) to avoid that bottleneck entirely.

Mixed hardware is fine — plan for it. If the lab combines NVIDIA-GPU desktops with one or more Apple Silicon Mac minis, treat the difference as curriculum, not friction. The NVIDIA boxes carry the vLLM/TGI production-serving story; the Mac serves through Ollama, LM Studio, or Apple's MLX. The unifying idea is the OpenAI-compatible API — every node, whatever its engine, exposes the same interface, so they all sit behind one LiteLLM gateway in Level 3. A Mac mini also turns the exo clustering experiment from a stretch into a natural fit, since exo targets Apple Silicon directly.

Security is part of the curriculum, not a footnote

Two teachable moments are built into the tools. The llama.cpp RPC backend explicitly warns never to run it on an open network — a perfect entry point for firewall, network-isolation, and "why does this matter" conversations. And the LiteLLM gateway issues API keys, which makes access control concrete. Keep the lab on an isolated segment; treat the security posture as something students design, not something IT hands them.

Pilot shape → course shape

As a "little bet," this runs cleanly as a club or independent study: everyone through Level 0–1 together, then students climb at their own pace with the modules as their guide. When it becomes formal CS courses, the seven levels map naturally onto units — Levels 0–2 as an introductory course, Levels 3–4 as an intermediate systems course, Levels 5–6 as an applied/capstone course. The certification map gives each course a concrete external credential to point at.

Honest caveats & what to re-check

This field moves monthly. A few things in here will drift, and it's better to name them than to let a student hit a dead link. Re-verify these at the start of each term:

  • Model versions. The specific "best small model" (exact Qwen / Gemma / Phi / Mistral release) changes constantly. The families and licenses are stable; pin the exact version the week you teach.
  • MCP spec version. A large revision landed in mid-2026; confirm the current spec version on the official site before building materials around it.
  • Agent frameworks. LangChain/LangGraph and Microsoft's AutoGen are changing fast (AutoGen is mid-reorg). smolagents and the OpenAI Agents SDK are the steadier bets for teaching; pin versions in any handout.
  • Certification details. Exam codes and prices shift (Azure already moved AI-900 → AI-901). Confirm on the vendor store before budgeting or printing.
  • Clustering tools. exo and the llama.cpp RPC backend evolve weekly; verify hardware support and status before a lab session depends on them.
What's solid

The shape of this progression is stable even as the tools churn: run → serve → network → extend → agents → build is how the real work is structured, and the OpenAI-compatible API is the through-line that keeps local models portable across every tool a student will meet. Teach the shape; swap the specific tools as they change.
